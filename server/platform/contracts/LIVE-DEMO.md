## Connect the existing screens

Run both applications behind **server-mediated authenticated access**. Store API URLs and application credentials in Next server-only environment variables, never `NEXT_PUBLIC_*`, client bundles, localStorage or query strings. A practical synthetic-demo BFF uses an authenticated, HttpOnly, SameSite session mapped on the server to one fixed role/customer. Validate that session and CSRF/origin on mutations; allowlist routes/methods and validate payloads. Do not implement an arbitrary forwarding proxy or let a browser select credentials/customer IDs. Use separate mappings for Veriq admin/investigator, Cedar customer C1, and authorized Cedar staff. Simulator and feed/source credentials stay operator/server-only; simulator actions are never normal customer navigation. The Python backend's static bearer principals are real API authorization, **not SSO**; no identity-provider verification is implemented.

Native rehearsal defaults: Veriq `http://127.0.0.1:8610`, Cedar `http://127.0.0.1:8611`, model `127.0.0.1:8181`. Credentials are generated privately per named run in `server/platform/var/rehearsals/<run>/runtime.json`. The administrator configures a trusted BFF from that private file; never copy the entire file to the frontend/browser. Frontend mock adapters are not yet an implemented API integration.

## Async, errors and review states

For every request, show loading while pending; show empty lists/profile=null as unconfigured/no records, not success. Keep the last successful evidence view while polling fails, with a visible stale/error indicator. Handle 401 (session), 403 (permission/revoked source), 404 (disabled or hidden record), 409 (conflict/incomplete setup), 422 (invalid input), 429 (bounded queue), 502/503 (upstream/database) distinctly; do not replace them with mock results.

Poll list/intents/tasks/steps every 2–3 seconds while pending; back off to 5–10 seconds when idle or unavailable. Model requests can take minutes on CPU. Do not call synchronous `/inference/evidence/...` or `/analyze` from the demo flow. A completed task can be quarantined, invalid_model_output, inconclusive, budget_exhausted, invalidated or cancelled. A reviewable assessment is a candidate. Source facts, rule-verified derived findings and unverified hypotheses must remain visually separate. Model endpoint reachability and historical real-generation receipts are separate from qualification; the preserved qualification result remains **0/4, unqualified**.

When latest_revision_id changes, preserve prior results with a superseded revision badge and show current automatic processing separately. If steps are redacted after source revocation, remove cached model/tool content. A stronger compatible model is chosen using the operator's deployment configuration, not a frontend-only alias change.

The JSON action map contains required request/schema references, response examples from the recorded HTTP rehearsal where available, state handling and actual verification provenance. Unsupported design controls: enterprise SSO/group mapping, general connection-string administration, arbitrary external source discovery, model installation/selection through browser, “production approved”, and assumed successful AI extraction. Present them disabled with the stated limitation rather than fabricate an endpoint.
