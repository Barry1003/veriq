# ADR-001: initial implementation of VERIQ-ARCH-001

Date: 2026-10-21. Status: implemented foundation. Owner: Daniel; implementation produced with OpenAI Codex assistance. No old repository was cloned or copied; no remote was configured.

## Application and persistence boundaries

Two independent FastAPI applications use different databases, bearer credentials and processes. They share only reusable source contracts and implementation utilities. The Cedar connector uses a real HTTP feed. Veriq never imports Cedar's financial service into its runtime domain, opens Cedar's DB, or exposes a banking write operation. Synthetic development bootstrap/demo scripts know both applications' private development credentials; the deployed Veriq service receives only the Cedar feed credential.

Python/FastAPI/Pydantic provide validated contracts and generated OpenAPI quickly. SQLAlchemy 2 and Alembic support PostgreSQL deployment with SQLite for an executable development fallback. This follows SQLAlchemy's [transaction context pattern](https://docs.sqlalchemy.org/en/20/orm/session_transaction.html). The lockfile pins the actual resolved versions. No graph/vector DB or broker is required for these queries.

`domain_records` stores indexed scope, kind, unique key, clearance, timestamps and immutable JSON snapshots. `source_feed` has monotonic sequence cursors. Domain services own all semantic validation. This compact relational document representation is a foundation tradeoff: it is portable and inspectable, but it does not yet provide database-level foreign keys/checks for every relationship encoded inside JSON, or scalable query plans for every domain projection. Move hot paths into dedicated relational tables as query/load requirements become known. No graph semantics are faked: projections carry typed edges and explicit evidence/assertion IDs.

PostgreSQL transaction-scoped advisory locks serialize dependent Veriq projections across sources within one installation; Cedar serializes scope mutations that emit feed records as well as locking account rows for reservations and reconciliation. This prevents a PostgreSQL sequence allocated by an uncommitted transaction from being skipped when a later transaction commits first. SQLite acquires `BEGIN IMMEDIATE` before reads to avoid stale concurrent balance/revision updates. It is a single-writer developer mode. A pull page is atomic; its cursor advances only after every envelope is processed. A stale concurrent pull is rejected for retry. Model calls occur outside database write transactions and are bound to the original immutable evidence/revision.

## Identity and source authority

Installation scope is the exact institution/environment pair from bank-controlled configuration. Entity `native_id` is a bank-assigned institutional identifier shared by its authorized sources, not a display name and not the source-native record ID. UUID5 of scope and that bank identifier supplies stable canonical identity. Renaming never changes identity. Explicit matching bank identifiers reconcile aliases/names with source provenance. Equal names with different identifiers remain separate and resolve as ambiguous. There is no silent fuzzy matching. Cross-namespace identity binding/merge requires a future reviewed decision contract.

Source registration grants record families, contextual authority, maximum classification and an authorization reference. A source-specific high-entropy secret authenticates ingestion; its hash is stored and omitted from reads. An `authorization_ref` alone authenticates nothing. Structured sources with structure authority, accepted schema, semantic types, correct scope and matching grant produce accepted knowledge. A document source has authority only for document evidence, never automatic structure acceptance.

AI extraction creates candidate snapshots. Candidates do not reserve canonical entity types or alter accepted context. Authorized reviewers accept/reject with rationale; accepting a candidate also checks existing identity compatibility. Reconciliation of a conflicting financial status requires bank authority, never a model action.

## Time, provenance and conflict semantics

Envelopes preserve source identity, immutable source-native record ID, schema, source timestamp, payload, correlation ID, grant, classification and reception time. Duplicate identity+content returns the same evidence ID; changed content under that identity is rejected. Every accepted derived claim cites evidence IDs.

Structured knowledge events are **complete source snapshots** with half-open effective intervals `[valid_from, valid_to)`. A later effective snapshot replaces that source's prior snapshot only once accepted/known. It does not change a past query. An expired replacement does not resurrect older knowledge. Competing snapshots at the same effective time remain visible together. Document-derived reviewed claims are independent assertions, not replacement inventories. Reviews are append-only knowledge-time decisions. `at` reconstructs institutional time; `known_at` bounds the learned/accepted record history.

`uses_gateway` is functional for a route/time. Different accepted objects from any source remain contested; ingestion time does not choose authority. Other typed edges are explicitly many-valued. Same-version contradictory transaction records are preserved, labelled contested and excluded from correlation. Higher bank-issued status versions can update present understanding; old evidence and investigation revisions remain intact. No source is universally authoritative: customer text establishes a report; monitoring establishes a measurement; bank status establishes a recorded outcome, not automatically verified receipt.

## Detection and correlation

Operational detection is deterministic and independent of complaints. For each source/route/gateway stream, it considers samples whose timestamps fall in the previous five minutes, with a preceding 25-minute baseline. It triggers at 10+ attempts with 30%+ timeouts, or at 10+ attempts with 20+ baseline attempts, a 3x baseline rate and at least 15 percentage points increase. Reasons, counts, rates and source evidence are persisted. Separate monitoring sources never double-count one another's samples. Sources must supply disjoint attempt populations; overlapping aggregate windows are not deduplicated or prorated in this version. Late events are evaluated at their source timestamps; there is no generalized historical window recomputation scheduler yet.

Customer classification uses explicitly labelled keyword rules; recurring categories across channels create reported issues, never a common-cause assertion. Local inference can attach a schema-validated interpretation candidate without rewriting identifiers or deterministic classification.

An interaction-to-operation correlation requires an explicit bank transaction reference with matching customer ownership, recorded actual route/gateway, an uncontested accepted route relationship at the transaction time, an observation on that same route/gateway within five minutes, and a report within 24 hours after the transaction. Text similarity has no linking authority. This establishes contextual association, never causal certainty. Transaction time, source recording time and reception time are distinct in investigation timelines.

## AI authority and authorization

The inference boundary is a task-shaped OpenAI-compatible local endpoint, not an external proprietary SDK dependency. See [Ollama local compatibility](https://docs.ollama.com/api/openai-compatibility) and [structured output documentation](https://docs.ollama.com/capabilities/structured-outputs). Pydantic validates all task outputs; analytical statements must use supplied evidence IDs and permitted hypothesis/recommendation statuses; invented transaction references are rejected. Semantic relationships are validated again before even a candidate is stored. Model input is untrusted data under application instructions. Structured output does not establish semantic truth: results remain reviewable candidates. No inference method exposes financial mutations or consequential bank actions.

Bank-provisioned bearer credentials map server-side to scope, roles, optional customer ownership and clearance. Source credentials are separate. Retrieval filters classification before returning content. Workspaces retain the strongest contributing classification, including institutional context. Unauthorized evidence cannot reach a model task. Roles are coarse responsibilities; production integration needs institution-specific policy and SSO/credential lifecycle controls. Audit rows are application-append-only, not cryptographically tamper-proof against a database administrator.
