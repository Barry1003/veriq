# ADR 005 — Model-directed investigation, evidence-governed publication

Status: implemented engine; release acceptance blocked on actual reasoning capability.
Date: 22 October 2026. Baseline: v0.4.0, retained in the historical source archive.

## Decision

Reuse `ai_task`, transactional `processing_intent`, scoped persistence/locks, worker leases and source grants. An adaptive task commits one external generation and its permitted read-only action at a time into `investigative_step`, then requeues the same task. It does not create a second job system or recursively generate investigation revisions.

Separate model choice from final assessment. Choice outputs only action, investigative question and an optional typed tool request. The model can choose tools in any order, terminate inconclusively or request assessment. Assessment is a subsequent bounded generation with open hypotheses, supporting/weakening references, uncertainty and next checks. The server does not choose a final explanation from a sentence catalog. The legacy catalog-based analysis remains a separate compatibility mode.

Five capabilities query persisted evidence: transaction history, operational observations, institutional configuration/dependencies, customer issue context, and literal institutional source search. They accept bounded native identifiers/namespaces, literal search and optional valid time. They expose no SQL, code, filesystem, outbound URL or administrative capability. Queries scan at most 500 typed records and return at most three records/9,000 JSON bytes. Partial results, missing information and errors are explicit. Large records may not fit; absence is not certified completeness.

The initial context is revision-pinned and starts with up to two motivating records. Each read has its own recorded knowledge time and valid-time filter, so new authorized documents can be discovered after the seed. Every returned evidence ID/digest/grant is added to the task manifest. Current revision, principal, evidence digests, source grants, AI policy and lease are rechecked before reading, before another model sees returned data, and before publication. Newly discovered restricted data upgrades the task/run classification. Permission/revision changes invalidate rather than publish obsolete work. Payload-bearing history/run views are redacted if source visibility is lost.

Default budgets: five model generations, three tools and 12,000 accumulated context bytes. Deployment may configure bounded larger values (up to eight generations, six tools, 128,000 context bytes) for approved hardware. Each task freezes its budgets. Inference timeout/output/context settings remain runtime configuration, independent of institutional domain logic. A final request with no remaining generation or a full context terminates as budget exhausted. Missing tools/errors can inform another question, within the remaining budget.

## Publication boundary

- **Verified source fact:** server-read exact scalar field/value with source identity, authority and valid/knowledge time. This verifies what the cited source records, not independent truth of customer/document content. Truncated text cannot certify an entire field.
- **Supported derived finding:** a small independently checkable predicate with cited premises (processing completed but receipt unverified; valid-time configured/actual execution mismatch; customer failure-language/completion co-occurrence, with semantic meaning left for review). Contested/superseded or incomplete premises fail closed. New unsupported derivations remain hypotheses.
- **Hypothesis:** open model-authored explanation, with model-proposed supporting/weakening evidence and next check. Citations establish reference existence only; their relevance/entailment and the hypothesis itself remain explicitly unverified.
- **Contradictions/unknowns/actions:** typed validated discrepancies separately from model-proposed uncertainty and recommendations. No financial action or institutional knowledge approval is delegated to the model.

Only a validated assessment becomes a `reviewable_assessment` inference run with `acceptance=not_accepted`. Invalid source assertions are quarantined; malformed model output, exhausted budgets, unavailability, invalidation and cancellation remain explicit. Task completion is not factual acceptance. Publication and task completion are atomic; repeated external generation after a crash is allowed, duplicated committed steps/results are not.

## Routing stabilization

Remove first-record association. Select effective transaction revisions within their issuing source's version history, retain conflicts across independent authorities and reject future-effective records for present association. A configured route is not an execution receipt. Incident/report association requires uncontested transaction-specific actual routing, owner/reference identity and temporal overlap; institution-wide newest configuration cannot override execution evidence. Material fingerprints include route/gateway, preserving historical revisions when routing changes.

## Compatibility and migration

No new relational schema is necessary: existing scoped `domain_records` supports the new step kind and task fields. Alembic head remains 0002. Existing v0.4 routes, required input fields and legacy analysis are retained. New adaptive endpoints are additive. `AI_INVESTIGATION_MODE=adaptive` selects automatic adaptive analysis through the existing outbox; default legacy mode protects prior demonstrations. `deploy/compose.adaptive.yaml` is the explicit opt-in overlay. Cedar source is byte-identical to v0.4.0.

## Consequences and limits

This engine supports genuine evidence-dependent model choices; controlled tests demonstrate different subsequent queries for different discovered evidence. That does not prove a real model can investigate well. The available 0.5B model failed the frozen reasoning cases. No successful unfamiliar real-model adaptive investigation is claimed. Production use needs a capable, independently qualified bank-hosted model and current deployment/security testing.

Identity remains exact namespace/native-ID based. Tools do not perform fuzzy identity merging, broad semantic search or implicit cross-namespace financial reconciliation. Static actor configuration, bounded relational scans, incomplete-result handling, valid-time refresh driven by subsequent material events, and production IAM/HA/secret rotation remain documented constraints. No arbitrary source truth or general natural-language entailment checker is claimed.

Final routing stabilization distinguishes execution receipts from reconciliation-only status/time, and generation receipt summaries are durable before final assessment publication. Customer discrepancy proof verifies literal failure-language co-occurrence and bank status/ownership; it does not certify free-text meaning or a logical contradiction. General language interpretation remains unverified.
